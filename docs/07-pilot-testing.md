## 4. Регрессия после исправлений

После каждого исправления дефекта:

1. Автотесты: `docker compose exec web python manage.py test` (все тесты проходят) и зелёный CI.
2. Выборочная проверка критического пути вручную: TC-02, TC-06, TC-10, TC-11, TC-15, TC-20, NT-02.
3. Нагрузочная проверка (если менялся код запросов, настройки сервера или БД): NT-01.
4. Результат записать в реестр: дата, версия, «регрессия пройдена».

## 5. Критерии готовности к промышленной эксплуатации

1. Нет открытых дефектов с приоритетом «Критический» и «Высокий» (или есть обоснованное решение о принятии риска).
2. Чек-лист пройден, критические сценарии (TC-02, TC-06, TC-10, TC-11, TC-14, TC-15, TC-19, TC-20, NT-02) без дефектов.
3. Нагрузочная проверка NT-01 выполнена.
4. Резервное копирование и восстановление проверены по руководству администратора.
5. Документация актуальна.
