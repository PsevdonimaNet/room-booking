# Описание API

Интерактивная документация (Swagger UI): `/api/docs/`. Схема OpenAPI: `/api/schema/` (можно скачать как `openapi.yaml`). Этот файл дополняет её примерами.

## Аутентификация

Сессия (после входа через сайт) или HTTP Basic (логин и пароль). Для изменяющих запросов с сессией нужен заголовок `X-CSRFToken`. Без авторизации: 401 или 403.

## Формат ошибок

```json
{"error": {"code": "booking_conflict", "message": "Переговорная уже занята на выбранное время.", "details": {}}}
```

| HTTP | code | Когда |
|---|---|---|
| 400 | `validation_error` | нарушены правила бронирования или неверные параметры |
| 403 | `forbidden` | недостаточно прав |
| 409 | `booking_conflict` | время занято |
| 409 | `invalid_state` | действие недопустимо в текущем статусе (повторная отмена и т.п.) |
| 503 | `service_unavailable` | недоступна БД (заголовок `Retry-After`) |

Ошибки проверки формата полей (например, не указано `room`) отдаёт DRF в стандартном виде: `{"room": ["Обязательное поле."]}`.

## Эндпоинты

| Метод | Адрес | Описание | Доступ |
|---|---|---|---|
| GET | `/api/rooms/` | список комнат (пользователю только активные) | авторизованные |
| POST | `/api/rooms/` | создать комнату | администратор |
| GET, PUT, PATCH | `/api/rooms/{id}/` | просмотр, изменение | чтение: все, изменение: админ |
| DELETE | `/api/rooms/{id}/` | отключить комнату (мягкое удаление) | администратор |
| GET | `/api/rooms/{id}/availability/?date=YYYY-MM-DD` | занятость по часам | авторизованные |
| POST | `/api/bookings/` | создать бронь | авторизованные |
| GET | `/api/bookings/?room=&status=` | история (свои; админ все) | авторизованные |
| GET | `/api/bookings/{id}/` | одна бронь | владелец или админ |
| POST | `/api/bookings/{id}/cancel/` | отменить | владелец или админ |
| POST | `/api/bookings/{id}/approve/` | подтвердить заявку на VIP | администратор |
| POST | `/api/bookings/{id}/reject/` | отклонить заявку на VIP | администратор |
| GET | `/api/bookings/export/?date_from=&date_to=&room=&status=` | экспорт в CSV | администратор |

## Примеры

### Список комнат

```
GET /api/rooms/
```

```json
[
  {"id": 1, "name": "Альфа", "capacity": 6, "location": "2 этаж, левое крыло",
   "description": "Маркерная доска и телевизор.", "is_active": true, "is_vip": false}
]
```

### Создание брони

```
POST /api/bookings/
{"room": 1, "start": "2026-11-25T10:00:00+03:00", "end": "2026-11-25T12:00:00+03:00"}
```

Ответ `201`:

```json
{"id": 5, "room": 1, "room_name": "Альфа", "user": "ivan",
 "start": "2026-11-25T10:00:00+03:00", "end": "2026-11-25T12:00:00+03:00",
 "status": "confirmed", "created_at": "2026-11-23T09:15:00+03:00", "cancelled_at": null}
```

Для VIP-комнаты `status` будет `pending` до решения администратора.

### Конфликт

Ответ `409`:

```json
{"error": {"code": "booking_conflict", "message": "Переговорная уже занята на выбранное время.",
 "details": {"conflicting_booking_id": 5, "start": "2026-11-25T10:00:00+03:00", "end": "2026-11-25T12:00:00+03:00"}}}
```

### Нарушение правил

Ответ `400` (например, 5 часов):

```json
{"error": {"code": "validation_error", "message": "Длительность бронирования: от 1 до 4 часов.", "details": {}}}
```

### Занятость

```
GET /api/rooms/1/availability/?date=2026-11-25
```

```json
{"room": 1, "date": "2026-11-25",
 "slots": [{"hour": 8, "start": "2026-11-25T08:00:00+03:00", "end": "2026-11-25T09:00:00+03:00",
            "busy": false, "booking_id": null, "pending": false}]}
```

### Экспорт CSV

`GET /api/bookings/export/?date_from=2026-11-01&date_to=2026-11-30&status=confirmed` возвращает `text/csv`: кодировка UTF-8 с BOM, разделитель `;`, колонки: ID, Комната, Пользователь, Начало, Конец, Часов, Статус, Создано.

## Правила бронирования

Целые часы; длительность от 1 до 4 часов; рабочее время 08:00-20:00 (локальное время системы); начало не в прошлом; ожидающая подтверждения бронь тоже занимает слот.
